数据来自 PAD-UFES-20：2,298 张公开、去标识的临床照片及配对资料。网页展示其中 12 个固定样本。

第一次演示，先做这四步

  1. 打开网页，点右上角“中文讲解”。

    在“选择公开样本”里选一条，先看照片和旁边的年龄、部位、症状。

  2. 点“让模型计算”。

    等下载和计算完成。首次较慢；之后换样本会复用已加载的模型。

  3. 比较三张结果卡。

    “只看照片”“只看临床资料”“照片＋临床资料”可能给出不同类别。再看“数据集提供的标签”，检查这一例有没有答对。

  4. 向下看“加入临床资料后，整体表现变好了吗？”

    这里是事先保存的整个测试组结果，回答“总体是否有帮助”。不要只凭一个样本下结论。

想多看一步，再展开“再看两种更复杂的融合模型”，比较 MetaBlock 和 HEALNet。第一次演示不必先记住这些名字。

它真正做了什么 AI？结果说明什么？

已训练好的图像编码器先把照片转成数字特征；本项目训练的预测层再学习“这些特征、临床字段和数据集类别之间有什么关系”。点击按钮时，浏览器实际运行保存的模型权重。

这次固定实验里，加入临床资料比只看照片表现更好。

但只看临床资料的模型也很有竞争力。所以不能反过来说“增加照片一定更好”，也不能据此宣布某种复杂结构总是最好。

表格里的 Macro-F1 是兼顾每个类别的分类分数，越高越好；旁边区间表示这次评估的不确定性。单个样本卡片里的百分比是模型类别得分，不是已验证的患病概率。

这是一个回顾性研究原型，不用于诊断。这里没有聊天 Agent，也没有连接医院。分类本身用机器学习完成，不需要大语言模型 API。

在哪里运行？

最简单：使用上方在线链接。静态网页由 GitHub Pages 提供，模型在访问者的电脑上计算，不调用付费 AI API。

本地 Python API 是另一个服务化练习，包含输入校验、模型版本和一个模拟审核流程；它不是网页演示的必需条件。启动方式在 README 的 Run locally。

不要直接双击应用的 index.html 来运行模型：浏览器会限制本地文件读取。这个说明页可以直接双击，在线演示则用上方按钮打开。
